# modules/billing — 余额充值与支付确认

这个模块管理用户钱包读取、普通充值订单、乐收赢支付通知和主动查单补偿。充值请求只接受金额、充值意图和扫码支付品牌，不接受旧运行任务的恢复编号。历史订单上的恢复关联保留为只读审计字段，可通过订单编号或原充值意图查询。

## 文件

- `types.ts` 定义内部充值订单、钱包、仓储端口和固定错误。历史恢复关联仅出现在订单读取类型中，不属于新建输入。
- `repo.ts` 实现订单、支付尝试、回调事件、钱包与资金流水的 PostgreSQL 事务。创建订单按账户锁限制并发数量，并核对同一充值意图；新订单的恢复关联固定为空。仓储不读取或修改旧待恢复用量表，不替换恢复意图。可信迟到回调继续按原订单精确入账，保留历史关联与支付身份。
- `service.ts` 编排普通充值、按订单编号或充值意图查单、通知验签和入账。相同意图不重复下单；预下单超时只查询原支付流水。旧恢复输入在创建订单前被拒绝，未通过验签的通知不写入回调事件表。
- `reconcile.ts` 在 API 进程中清理到期支付动作并领取待查订单。每笔订单最多主动查询 120 次且不超过 24 小时，之后仍接受可信成功回调；多副本由 PostgreSQL 租约协调，单进程不重叠执行。网关关闭时只清理过期动作。
- `handlers.ts` 使用共享严格协议校验输入并返回普通订单视图。响应不包含历史恢复关联、机构号、商户号、支付流水或网关原文。
- `routes.ts` 注册钱包、普通充值、按订单编号或充值意图查询和支付通知端点。浏览器写入使用 Cookie 与精确来源校验，网关通知不依赖浏览器凭据。

## 上下游

路由由 `bootstrap/routes.ts` 挂到 `/api/v1`。处理函数与后台调度器使用 Fastify 注入的 PostgreSQL、充值配置和支付网关。表结构由追加迁移维护；本模块不改写历史恢复关联，不保存机构密钥、原始回调或完整网关响应。
