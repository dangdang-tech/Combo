# 前端接入合同与责任边界

本文件是交接所需的行为合同和数据建议，不是已经发布的新 API。现有 Combo 支付协议、支付中台和锁定 SDK 的合同优先。Combo #357 已接受主动套餐、业务点数和 KOL 实收增量，不改旧 v1 范围。具体端点、字段名、计价单位、收银台渠道及后端接入状态由 xz1220 在 Combo #357 与 SDK PR #7 中落实。

## 权威来源

业务服务保存原始问题、命盘、话题、目标年份、前文以及 `operationId`、`callId`。浏览器只能引用当前用户有权限的业务操作，不得通过跳转参数重新构造一条付费调用。支付中台保存价格快照、订单、渠道结果、到账、资金预留与流水；浏览器不直接修改余额，也不根据二维码、成功页面或用户声明判定支付成功。

Host 只消费平台签发的短期支付凭证，并使用当前登录用户向 Combo 解析托管收银台。不得信任 Agent 提供的 URL、二维码、金额或用户标识。订单页面只能展示当前身份查询得到的结果，错误、超时和未知字段必须按现有协议失败关闭。

## 需要对接的视图数据

| 视图     | 必需内容                                                                 | 权威方与限制                                                                                     |
| -------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 余额     | 可用余额、展示单位、是否允许主动充值                                     | 支付中台给出可用金额与预留语义；观照点和金额之间的映射必须明确，前端不能自行换算。               |
| 套餐     | 稳定套餐标识、点数或权益、货币、整数金额、有效报价、可用状态             | 由配置与支付服务返回。演示固定套餐必须被替换，不能静默降级为默认正式价。                         |
| 问事发送 | 原操作引用、当前报价、报价版本、可用点数、发送后的资金状态               | 成本显示在发送按钮；报价由服务端返回，点击发送只授权当前问题与当前报价，不在浏览器执行真实扣点。 |
| 支付订单 | 稳定订单引用、状态、报价快照、有效期、实际支持的渠道、二维码或收银台凭证 | 当前身份经平台授权查询；扫码图来自该订单的 `qrImage`，不能接受 Agent 提供的任意图片或收款链接。  |
| 回到问题 | 原操作引用、可授权恢复动作、当前业务状态、已保存结果                     | 由观照业务服务返回。到账与生成解读是两个状态。                                                   |
| 明细     | 当前用户可见的充值、使用、预留或释放记录，以及分页信息                   | 不通过客户端聚合猜测正式余额，列表只显示服务端支持的记录种类。                                   |

## 十个界面状态

| 状态       | 产品显示与动作                                 | 接入规则                                                                                                   |
| ---------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 点数充值   | 展示可用余额与套餐，继续充值。                 | 能力关闭时不能发起充值。套餐加载失败时应显示重试，不能使用演示价。                                         |
| 问事与发送 | 右上角显示可用点数；发送按钮直接显示本次成本。 | 点击发送继续当前问题，无每次扣点弹窗。报价变更时先更新展示并要求重新发送，不能接受旧报价后静默按新价执行。 |
| 点数不足   | 输入框下轻提示差额，保留原问题。               | 保存并绑定原操作。支付由标准不足余额响应或已批准的主动充值入口发起。                                       |
| 收银台     | 展示订单、渠道二维码、权益、金额和有效期。     | 使用平台托管收银台，不生成自己的收款地址。                                                                 |
| 等待确认   | 已付款可查询；可先返回原问题。                 | 查询具有超时、重试上限及离开后的恢复入口；查询不能扣费或重复发起模型调用。                                 |
| 结果未知   | 提示暂无法确认，先不要再次支付。               | 继续查询原订单。不能把超时判成未付款，也不能自动换一笔订单。                                               |
| 订单过期   | 区分已付款待核实与尚未付款重新选择。           | 由服务端确认关闭。对可能迟到的付款保留核实与入账路径。                                                     |
| 充值成功   | 显示到账数与当前余额，返回原问题。             | 必须收到服务端已到账状态。回调、查询、重复点击都不能重复入账。                                             |
| 回到原问题 | 到账后继续原解读，保留命盘、问题、年份和前文。 | 沿用原 `operationId`、`callId` 与报价；已有预留的调用不得再次扣费。新问题的成本仍显示在发送按钮上。        |
| 订单记录   | 查询待处理与已完成订单，查看使用记录。         | 刷新、重新登录、换设备和跨用户隔离必须由真实服务验证。                                                     |

## 二维码与价格

沿用观照既有收银台的 `order.qrImage`、支付方式和有效期数据。扫码图、金额与订单状态必须属于同一授权订单；过期或失败时隐藏二维码。付款结果未知时保留原订单查询，不换二维码诱导重复付款。「我已支付」只触发查询，不能据此增加余额。生产只展示服务端返回且实际可用的渠道；本预览的微信与支付宝是演示选项，不代表 SDK 已支持。

账户右上角显示服务端可用点数，扣除已预留金额后的语义必须明确；不能用演示 2 / 20 点作报价缺失时的默认价。报价失败时禁用发送并提供重试。标准 / 深入是交互样本，正式模式与定价由业务配置决定。

## 幂等与中断

前端预览用稳定的演示订单号阻止未处理订单重复创建，并用内存集合避免重复到账；这些只验证界面反馈。真实幂等必须在服务端成立。一个订单多次成功通知只能入账一次；一个业务操作多次恢复只能持久化一次结果，并按合同扣费或使用一次预留。

对原有不足余额支付，平台到账后为原调用预留资金，业务恢复原请求。「继续原来的解读」恢复已有操作，不再次打开扣点确认，也不能实现为第二次资金扣除。只有尚未预留的新业务请求，才按已展示并接受的报价进入业务计费合同。

用户离开收银台后，恢复入口应由当前身份读取未结束操作。身份失效时先登录，再回到经过授权的原操作；不能将命盘、问题正文、支付凭证或用户标识放进外部跳转 URL。日志与截图不保存令牌、邮箱、真实问题或支付凭据。

## 开放条件

正式展示套餐前需要落实主动充值能力开关、人民币或平台金额与观照点的映射、资金预留语义、有效期及退款说明、当前真实支持的渠道。KOL 实收由 #357 的服务端账务增量负责，前端套餐不能把模型成本、平台余额和业务点数混为同一金额。没有能力返回时隐藏不可用入口，不展示没有实现的支付方式。当前原型不提供优惠、赠送比例、退款承诺、发票、订阅、自动续费或跨币种结算。

观照正式环境目前仍关闭支付。本交接不包含生产开关、支付凭据、渠道创建、真实订单或部署操作。
