# 观照支付接入与设计预览

本目录基于 [Combo PR #374](https://github.com/dangdang-tech/Combo/pull/374) 的可运行前端接入观照套餐服务，关联 #308 与 #357。页面使用 SDK 的独立 commerce 客户端读取同源登录、套餐、点数和订单，已替换原十状态 Mock 入口。旧设计可从 PR #374 的历史版本查看。

## 代码与责任

`source/commerce-page.tsx` 是实际接入页面，复用既有主题与响应式样式；`source/commerce-session.ts` 负责身份复核、原请求保存、跨标签页串行下单与订单找回；`source/commerce-session.test.ts` 验证这些边界。支付结果与点数均来自服务端，前端没有入账、扣点或伪造成功的路径。

`source/app/payment-lab/` 保留既有样式及 Next 兼容入口，组件挂载后才读取浏览器会话。`main.tsx` 渲染实际页面。`vite.config.ts` 固定资源前缀 `/mingli/payment-sdk/`。`CONTRACT.md` 记录实际接口与旧设计合同的适用边界，`ACCEPTANCE.md` 区分自动化、浏览器和真实付款验收。

## 安装与构建

需要 Node 24。SDK 使用 `package.json` 中锁定的 0.3.0 源码版本。旧 0.2.0 只有钱包支付接口，没有 commerce 方法，不能替代本次套餐接入。

```bash
npm install --workspaces=false --package-lock=false
npm run typecheck
npm test
npm run build
npm run dev
```

本目录不在 Combo pnpm workspace 匹配范围内，独立安装不会改变根锁文件。CI 需要单独执行本目录检查。实际浏览器入口是 `/mingli/payment-sdk/`；本地开发入口是 `http://127.0.0.1:4597/mingli/payment-sdk/`。

实际支付必须运行在服务端允许的 HTTPS Host 下。开发服务器不会代传真实会话，不改 Origin，也不把支付请求代理成受信请求。在本地默认入口看到登录未确认属于正常失败关闭；不能作为真实支付失败的证据。

## 套餐支付流程

登录返回路径为 `/mingli/login?next=<支付页本地路径>`。页面先读取当前用户，再读取 `/v1/commerce/catalog/mingli` 与 `/v1/commerce/account/mingli`。所有金额为人民币分，观照点为独立整数单位；页面展示服务端套餐，不使用设计样本价格。

用户确认套餐后，页面先持久化当前用户与原 `requestKey`、套餐、版本和支付方式，再调用 SDK 创建订单。浏览器存储失败就不下单。丢失响应、刷新或另一个标签页打开时查询原 key；并发点击经过浏览器锁串行处理，排队期间已经到账也不会自动再建一单。

付款码只展示服务端返回的 PNG，既不自行生成收款内容，也不打开未知付款链接。缺码、结果未知、查询失败或本地付款窗口到期时隐藏二维码，继续查询原订单。轮询最多三分钟；离开页面暂停可见查询，回到页面重新核身份和结果。独立到期定时器在轮询结束后仍撤下二维码。

订单 `completed` 才显示到账，再读取服务端余额。按钮不能把“我已付款”变为成功，页面不会本地增加点数。

## 原问题续接

业务原入口可以携带 `?continue=<operationId>` 进入本页。页面从当前用户的 `/mingli/api/combo/operations` 列表确认该请求属于套餐流程，到账后提供明确的“确认继续原请求”按钮，目标为 `/mingli/?resume=<operationId>`。普通导航只返回 `/mingli/`，不会自行续接。该业务首页沿用服务器保存的命盘、问题、上下文和结果，执行既有恢复与结算流程；支付页不提前确认完成、不生成新问题，也不直接调用内部计费接口。

公开列表最多返回最近二十条未确认操作，不含问题正文。未找到请求时仅提供普通返回，不显示虚构的原问题、报价或已保存承诺。支付页不把问题正文、凭证或用户标识放入 URL。

## 已知服务边界

现有套餐接口没有 wallet `paymentToken`、托管钱包 URL 或公开关单／换单接口。它与 SDK 原钱包客户端并列，不能互相替代。`closed` 只表示本地付款窗口结束，不能证明渠道关单；当前页面会保留未核实订单并阻止另开订单。原 key 查询不到时也保持待核实，不自动重新提交。

历史待处理订单会影响继续购买，需服务端核实后处理。最近五十单以外的跨设备找回、退款与 KOL 实收不由本页面实现。现有业务续接后端与套餐后端尚未全部纳入主线，部署本页面不代表它们已完成源码整合；不升级数据库，不开启钱包 V2 恢复开关。

## 历史设计证据

原预览的本地 20 点、320 点充值、30 点问题等布局样本只验证过模拟交互。对应代码可在 PR #374 的 `2cdc31c` 查看；本目录 `evidence/` 保留历史预览记录，不代表新入口的实际账户或账务验收。
