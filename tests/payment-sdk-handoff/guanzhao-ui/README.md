# 观照点数与支付流程设计交接

本目录交付观照的点数充值、扣点确认、订单查询和充值后回到原问题的前端设计。负责人为 xz1220，关联 [Combo #357](https://github.com/dangdang-tech/Combo/issues/357) 与 [Payment SDK #7](https://github.com/dangdang-tech/combo-agent-sdk/pull/7)。这是一份可运行的模拟交接包，未接入真实支付、账户或模型服务，未改变 Combo 现有产品代码和观照正式站的支付开关。

页面延续观照已经选定的浅色「朱砂纸本」与深色「墨夜观星」主题。点数、金额、问题和记录均为本地演示数据。100 点 / ¥10、320 点 / ¥30、800 点 / ¥68 是布局样本，不是正式定价，也不是 ChatGua 的已核实价格。

## 当前交付

`source/app/payment-lab/payment-lab.tsx` 包含十种界面状态和纯本地交互；`payment-lab.css` 包含基础布局，`payment-responsive.css` 包含平板、390 px 与 320 px 的适配。`source/app/theme-toggle.tsx` 是观照现有主题开关；`payment-tokens.css` 是从观照现有全局样式提取的主题变量、基础样式和开关样式。`source/app/payment-lab/page.tsx` 保留观照 Next 兼容路由入口，独立预览不会编译该入口。

`main.tsx`、`index.html` 和 `vite.config.ts` 提供独立预览。`CONTRACT.md` 说明接入时的数据责任和待确认能力；`ACCEPTANCE.md` 列出已运行检查及后续验收；`REFERENCE.md` 记录外部参考的实际观察范围。截图索引位于 `screenshots/README.md`，PNG 保留于本地验收产物；索引记录摘要，实际视觉可运行本目录预览。仓库预算门禁禁止二进制改动，因此截图不进入源码提交。

## 独立预览

将本目录复制到一个本地临时目录，进入副本后执行以下命令。依赖安装仅发生在该副本，不修改 Combo 工作区或根锁文件。

```bash
npm install --ignore-scripts --package-lock=false --workspaces=false && npm run dev
```

浏览器打开 `http://127.0.0.1:4597`。依赖精确版本列在本目录的 `package.json` 中。该目录不在 Combo 的 pnpm workspace 匹配范围内，因此 Combo 的构建与类型门禁不会自动验证独立预览；独立预览需单独构建和浏览器验证。

也可以把 `source/app/payment-lab/` 放入已有观照代码树的 `app/payment-lab/`。观照已经提供 React、Lucide、全局主题变量与 `app/theme-toggle.tsx`，不需要新的后端接口。执行观照的 `npm run typecheck` 和 `npm run build:server` 后，访问 `/mingli/payment-lab`。独立副本的 `payment-tokens.css` 不应重复覆盖观照的正式全局主题。

## 如何体验

初始余额为 20 点，已保存的问题是「那 2027 年呢？适合换一个工作方向吗？」，本次解读需要 30 点。点击「我的问题」会显示点数不足，接着选择套餐、进入收银台、进入等待确认。使用页面下方独立的「预览控制」模拟支付结果，到账后点击「回到原问题」，再次明确确认使用 30 点，最后在明细中查看充值与本次使用。

顶部「查看状态」可以直接查看全部十个状态；切换状态会重置为该状态的确定演示数据，不是实际订单状态变更。右上角切换深浅主题。刷新页面会重置演示账户与订单，主题偏好由现有主题组件记录。恢复历史真实订单、跨设备继续和刷新后恢复原任务属于接入验收，当前未实现。

收银台区域是不可扫描的设计占位。「前往收银台」在演示中只切换为等待页，不打开第三方页面。演示没有 `fetch`、支付 SDK 调用、真实登录、扫码、银行卡输入或外部支付链接。

## 视觉与交互约束

主界面采用纸色与墨色背景、宋体标题、细边框、方形按钮和朱砂强调色。主按钮只承担当前的一项确定动作；余额、扣点数量和订单状态靠文字说明，不依赖颜色。桌面套餐并排，窄屏改成纵向卡片；订单明细在窄屏改成两列记录。原问题在充值、支付结果与返回确认中持续可见。

「我已付款」只查询原订单，不把用户声明视为到账。结果未知时保留原订单，不能通过创建新订单替代查验；订单过期时明确区分已经付款与尚未付款。到账仅增加点数，继续解读仍需用户确认。真实接入必须遵循服务端资金预留和恢复合同，不能把演示中的本地加减点逻辑搬入生产。
